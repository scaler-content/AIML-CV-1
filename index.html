01

Can a computer see a cat?

You recognise a cat in a photo instantly. A computer receives something very different: a grid of numbers. Before any learning happens, the first job is to understand exactly what those numbers are.

An image is a mosaic of pixels

A digital image is made of tiny locations called pixels (short for picture elements). Each pixel records the colour at one point. Think of a photograph as a mosaic of tiny coloured tiles: from a distance it looks smooth, and zoomed in you see individual squares.

  • A grayscale image stores one number per pixel: 0 is black, 255 is white, values in between are shades of grey.
  • A colour image stores three numbers per pixel, one for each colour channel: Red, Green, Blue.

RGB: how colour becomes numbers

Many colour images use RGB: Red, Green, Blue. Each pixel stores three values, one per channel. In an 8-bit RGB image every value ranges from 0 to 255, and different mixes of the three channels produce different colours.

Image shape: organising the numbers

When a colour image is stored as a NumPy array or a PyTorch tensor, we need a convention for the three dimensions.

DimensionMeaningExample
HeightNumber of rows of pixels32
WidthNumber of columns of pixels32
ChannelsNumber of colour planes3 (RGB)
  • NumPy / PIL: [Height, Width, Channels] → shape (32, 32, 3)
  • PyTorch: [Channels, Height, Width] → shape (3, 32, 32)
  • PyTorch during training adds a batch dimension: [Batch, Channels, Height, Width] → shape (B, 3, 32, 32)

Think of the image as a stack of three aligned spreadsheets: one for red, one for green, one for blue. Every cell in every spreadsheet matches the same pixel location.

Could we simply flatten all these numbers into one long list and feed them into a regular neural network? Yes, but we lose all spatial information: the network no longer knows which numbers are neighbours or which ones form edges. The next section shows exactly what that costs.

04

Why do we need a CNN?

A fully connected (dense) network can classify images, but it has two serious problems.

  1. Too many parameters. A 224×224 RGB image has 150,528 inputs.
  2. No spatial awareness. After flattening, pixel (0, 0) and pixel (100, 100) are just two unrelated numbers. The network has no concept of neighbourhoods or edges.

Problem 1: the weight count explodes

With the defaults, the first layer alone needs 150,528 × 1,024 = 154,140,672 weights, about 154 million.

Problem 2: location-bound detectors

A cat's ear might appear near the left of one image and near the right of another. A dense network that learned to detect an ear at position (10, 20) has to learn ear detection again at position (10, 150), completely from scratch.

The experiment below uses the simplest possible dense detector: its weights are exactly the flattened image of the object at position A. The convolution filter is a small 3×3 patch of ones. Move the object around and compare.

def make_object_image(size, row, col, obj=3):
    im = np.zeros((size, size))
    im[row:row+obj, col:col+obj] = 1.0
    return im

images = {name: make_object_image(12, r, c) for name, (r, c) in zip("ABC", [(1, 1), (4, 4), (8, 8)])}

# Dense detector: weights = flattened image of the object at A
w = images["A"].flatten()
for name, im in images.items():
    print(f"Dense detector response to {name}: {w @ im.flatten():.0f}")

# Convolution filter: the same 3x3 patch of ones, slid across every position
k = np.ones((3, 3))
for name, im in images.items():
    resp = np.array([[(im[r:r+3, c:c+3] * k).sum() for c in range(10)] for r in range(10)])
    print(f"Filter response to {name}: peak {resp.max():.0f} at {tuple(int(v) for v in np.unravel_index(resp.argmax(), resp.shape))}")

Important

The dense detector gives exactly zero for B and C, because the three objects share no pixel positions. A dense detector is tied to the pixel positions it was built on: the same object elsewhere is invisible to it. A filter with the same weights reused at every position finds the object wherever it is, and tells us where.

Building a new detector for every possible location would be wasteful. Reusing the same detector everywhere is far more efficient, and that is the central idea of a CNN.

Definition

A CNN (Convolutional Neural Network) scans a small, reusable filter across the image, using the same weights at every position. This is called weight sharing. It solves both problems: far fewer parameters, and awareness of where patterns occur.

05

A filter scans the image

A filter (also called a kernel) is a small grid of weights, often 3×3. At each location the filter:

  1. Looks at a small image patch the same size as the filter
  2. Multiplies each patch value by the matching filter weight
  3. Sums all those products (and adds a bias)
  4. Records that single number as the output for that location
  5. Moves to the next location (by the stride) and repeats

This operation is called convolution (technically, cross-correlation). Think of a filter as a reusable pattern-checker: you slide it over every part of the image and ask, does this patch look like my pattern? The answer, a single number, is strong when the patch matches and weak when it does not.

Important

Filters do not have fixed meanings like "edge detector". They learn from data. Early layers often respond to edges and textures; deeper layers combine those into complex shapes.

Is this really convolution?

Technically it is cross-correlation. True convolution flips the kernel first. Deep learning libraries do not flip it, and since the weights are learned the difference does not matter in practice.

So is this filter an edge detector?

This particular filter is a hand-designed vertical-edge detector, used here for illustration. In a CNN nobody designs the filter: training decides the weights.

Verify, don't just trust

An AI assistant is handy for analogies and for checking arithmetic, but you must know enough to judge its answer. A good filter analogy has to include sliding, multiplying and summing, and weight reuse; many miss that the filter is learned and that the same weights are used everywhere. The formulas and code in this post are your ground truth.

06

Feature maps: where did the pattern appear?

A feature map (also called an activation map) is the grid of responses produced by sliding one filter over the entire input.

  • Each location records how strongly the filter responded at that position.
  • A high value means the filter's pattern was present there; a low or negative value means it was absent.
  • One filter → one output channel (feature map). A layer with 16 filters produces 16 feature maps stacked together.

Think of a map with a dot at every place a pattern was found: the feature map is a spatial record of where a pattern appeared. Different filters learn different patterns. Early layers typically respond to edges and colours; deeper layers combine these into textures, parts, and eventually whole objects.

Full code and output 
stripes = np.fromfunction(lambda r, c: np.where((r + c) % 4 < 2, 200, 50), (16, 16))

filter_horiz = np.array([[-1, -1, -1], [ 0, 0, 0], [ 1, 1, 1]], dtype=float)
filter_vert  = np.array([[-1,  0,  1], [-1, 0, 1], [-1, 0, 1]], dtype=float)

def conv2d(image, f):
    kh, kw = f.shape
    return np.array([[(image[r:r+kh, c:c+kw] * f).sum() for c in range(image.shape[1] - kw + 1)]
                     for r in range(image.shape[0] - kh + 1)])

for name, f in [("horizontal", filter_horiz), ("vertical", filter_vert)]:
    fm = conv2d(stripes, f)
    print(f"{name:<11} feature map {fm.shape}, response range {fm.min():.0f} to {fm.max():.0f}")
horizontal  feature map (14, 14), response range -150 to 150
vertical    feature map (14, 14), response range -150 to 150
Key insight

Both filters give a 14×14 feature map with a response range of −150 to 150: the answer is same. A diagonal stripe has both a horizontal and a vertical component, so both filters respond with equal strength. A filter's response depends on its weights and on the local pattern under it. Edit the filter above and the shape stays 14×14 for any 3×3 filter; only the values change.

07

How many parameters does a convolution layer have?

Parameters = Cout × ( Cin × Kh × Kw + 1 )
  • Cout = number of output filters
  • Cin = number of input channels
  • Kh, Kw = kernel height and width
  • +1 = one bias per filter

Worked example: 3 input channels, 16 filters, 3×3 kernel: 16 × (3 × 3 × 3 + 1) = 16 × 28 = 448 parameters.

Important

Image height and width do not appear in this formula. A conv layer trained on 32×32 images can be applied to a 224×224 image without changing any weights.

def conv_params(c_in, c_out, k):
    return c_out * (c_in * k * k + 1)

for c_in, c_out, k in [(3, 16, 3), (16, 32, 3)]:
    layer = nn.Conv2d(c_in, c_out, k)
    print(f"formula {conv_params(c_in, c_out, k):,}  |  PyTorch {sum(p.numel() for p in layer.parameters()):,}")

08

Stride, padding, and output size

Two settings control how a filter scans.

SettingMeaningDefault
Stride (S)How many pixels the filter moves at each step1
Padding (P)Zeros added around the border of the input0
Hout = ⌊H + 2P − KS⌋ + 1
  • H=32, K=3, P=0, S=1 → ⌊(32+0−3)/1⌋+1 = 30
  • H=32, K=3, P=1, S=1 → ⌊(32+2−3)/1⌋+1 = 32 (same size)
  • H=32, K=3, P=1, S=2 → ⌊(32+2−3)/2⌋+1 = 16 (halved)

Padding of 1 with a 3×3 kernel is the standard recipe for keeping spatial size constant.

Does stride 2 always halve the size?

No. It halves the size only when the numbers work out. For H=7, K=3, P=1, S=2 the formula gives ⌊(7+2−3)/2⌋+1 = 4, not 3.5. Without padding, H=32, K=3, S=2 gives 15, not 16. The formula, not a general rule of thumb, settles it; load those cases above to check.

09

The basic CNN architecture

A common beginner CNN follows one path. The convolution block is repeated to extract features, then a classifier turns those features into class scores. Select a block to see its role.

Visualizer · Anatomy of a basic CNN

BlockRoleWhy needed
Conv2dDetects local patterns with learned filtersSpatial feature extraction
ReLUReplaces negatives with zeroAdds non-linearity
MaxPool2dTakes the maximum in each 2×2 windowReduces size, adds location tolerance
FlattenConverts a 3-D tensor to a 1-D vectorConnects feature maps to the classifier
Linear (Dense)Weighted combination of all featuresLearns which features matter for each class

Early conv layers pick up local patterns such as edges and colours. Later layers combine them into more complex shapes. The classifier turns the final features into class scores: the conv layers collect local patterns, and the final Linear layer produces the scores.

Why do we need ReLU between layers?

Without a non-linearity, stacking several linear layers collapses into one linear operation. ReLU is what lets deeper networks learn more complex patterns.

10

A tiny CNN in PyTorch

Everything described so far maps directly onto a few lines of PyTorch. For a batch of RGB images shaped [batch, 3, 32, 32]:

class SimpleCNN(nn.Module):
    def __init__(self):
        super().__init__()
        self.features = nn.Sequential(
            nn.Conv2d(3, 16, kernel_size=3, padding=1),
            nn.ReLU(),
            nn.MaxPool2d(2),
        )
        self.classifier = nn.Sequential(
            nn.Flatten(),
            nn.Linear(16 * 16 * 16, 10),
        )

    def forward(self, x):
        return self.classifier(self.features(x))

model = SimpleCNN()
print("Output shape:", tuple(model(torch.randn(2, 3, 32, 32)).shape))      # (2, 10)

total_params = sum(p.numel() for p in model.parameters())
dense_params = (3 * 32 * 32) * 512 + 512 + 512 * 10 + 10                   # dense 3072 -> 512 -> 10
print(f"Total parameters: {total_params:,}")
print(f"Equivalent dense (3072->512->10): {dense_params:,}  ({dense_params / total_params:.0f}x more)")

Recap

Key takeaways

  1. An image is a grid of numbers. Each pixel holds one number per channel (3 for RGB).
  2. Shape matters. PyTorch stores images as [Batch, Channels, Height, Width].
  3. A dense detector is tied to pixel positions. A filter reused everywhere finds the same pattern wherever it appears.
  4. A CNN filter is a small learnable pattern-detector that slides over the entire image.
  5. A feature map records where a filter responded strongly across the image.
  6. Weight sharing makes CNNs far more efficient than dense networks for images.
  7. Basic CNN flow: Conv → ReLU → Pool → (repeat) → Flatten → Dense → Class scores.

Can you explain it? Interview checkpoint

Try to answer each question in your own words, then flip the card.

One sentence: what is the single biggest reason we do not feed images straight into a dense network?

Two problems stack up: the parameter count explodes (about 154 million weights for one 1,024-neuron layer on a 224×224 RGB image), and flattening throws away spatial structure, so a detector built for one position cannot recognise the same object elsewhere.

Try it yourself

Extend SimpleCNN with a second conv block. What happens to the output shape?

Work it out

After the first block the tensor is [B, 16, 16, 16]. A second block Conv2d(16, 32, 3, padding=1) → ReLU → MaxPool2d(2) keeps 16×16 through the conv (padding 1, K=3) and halves it in the pool, giving [B, 32, 8, 8]. Flatten then yields 32 × 8 × 8 = 2,048 values, so the final layer must change to Linear(2048, 10). The conv layer itself has 32 × (16×3×3 + 1) = 4,640 parameters.
